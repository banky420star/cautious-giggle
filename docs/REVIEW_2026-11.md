# Pipeline review — November 2026

The review was split across four areas: execution, risk/decision, training/eval and repo hygiene. Findings were cross-checked in code before fixing. Regression tests are in `tests/test_review_fixes.py`. 20 of those 21 tests fail on the pre-review code.

## Fixed in this change

### Execution (`Python/mt5_executor.py`)
- **Filling mode:** `symbol_info().filling_mode` is now decoded as a bitmask (FOK=1, IOC=2). Before, symbols that allow only FOK or only IOC got retcode 10030 "invalid fill" on every order.
- **Trade counting:** a trade is recorded only when an order actually executes. Before, every 20-second no-op reconcile counted as a trade, so the 50/day per-symbol limit was hit in about 17 minutes and the bot could no longer close positions.
- **Closes during a halt:** closes and reductions always go through. Only *opening or increasing* risk is gated by `RiskEngine.can_open`.
- **Error halt:** market-closed (10018), requote/price-changed (retried up to 3 times with a fresh tick), no-changes and connection retcodes no longer count toward the error halt. A successful order resets the consecutive-error counter.
- **Magic filtering:** positions are filtered by magic number (`[base, base+1000)`), so manual trades and other EAs are no longer closed or resized.
- **Failed close:** a failed close aborts the opposite-side open. Before, this could leave a hedged long and short at the same time.
- **Resizing:** a reduction is a partial close of the excess. Before, the bot closed everything and reopened, paying the spread twice.
- **Volume:** volume is normalized to `volume_step`, `volume_min` and `volume_max`.
- **`risk_percent`:** this config value is now enforced. Lots are capped so a stop-out loses at most that % of equity.
- **Deviation and SL/TP:** closes use the profile `entry_deviation`, not a hardcoded 20. SL modifies require a minimum improvement, and TP is no longer re-sent every cycle.
- **ATR and ticks:** ATR uses closed bars and is cached for 30 seconds. Zero or invalid ticks are rejected.

### Risk and decision
- **Supervisor flips:** a sign flip (long to short) is no longer treated as a "risk reduction", which had skipped the halt, daily-loss and cooldown checks.
- **PPO input window:** PPO live inference now uses the **latest** window of closed bars and the real position. Before, it used the *oldest* window (bars from 10 to 18 hours earlier) with a fake flat position.
- **Live bars:** the bot fetches 1000 *closed* bars (`start_pos=1`, so no repainting forming bar), skips stale feeds, and calls `symbol_select` at startup. It reconnects to MT5 with backoff if the terminal link drops.
- **Daily-loss guard:** this now uses realized plus floating P&L, recomputed every loop. Before, it used realized P&L only, refreshed every 10 minutes.
- **`risk_scalar`:** a value of 0.0 now blocks the trade. Before, the `or 1.0` default turned it into full size.
- **`confidence_threshold`:** this config value is now applied to the LSTM bias.
- **Missing models:** a missing PPO or Dreamer model no longer hands its weight to the LSTM, which made the target jump around. Set `trading.redistribute_missing_weight: true` for the old behaviour.
- **Dreamer weight:** the default is now 0. Dreamer is not evaluated by any promotion gate. Blend weights are BTC PPO 0.70 / LSTM 0.30 and XAU 0.60 / 0.40.
- **LSTM fail-closed:** the LSTM returns HOLD if its model or scaler is missing. It no longer trades on random weights or on a scaler fit to the live window. Dropout is always off at inference.
- **Supervisor cooldown:** the cooldown and trade alerts fire only when an order executed.

### Training and features
- **Lookahead fix:** a lookahead leak in the m15/h1/h4/d1 features is fixed. Each 5-minute bar now sees only fully closed higher-timeframe buckets. `test_features_have_no_lookahead` covers this.
- **Training env:** a flat action (target 0) now stays flat. Before, `sign(0) or 1.0` opened a long.
- **Profit log:** the per-step `profitability.jsonl` write is sampled (`AGI_ENV_PROFIT_LOG_EVERY`, default 500). Env throughput went from about 6.9k to about 12.5k steps/sec.
- **Feature count cache:** `feature_count_for_version` is cached. It was rebuilding a 300-row feature frame on every PPO prediction, and is about 16x faster now.

## Next (needs retraining or larger changes)
- **Evaluation:** use a chronological train/validation/test split. Today the eval windows sit inside the training data, and train and eval use the same data frame.
- **Promotion gates:** require positive net return after costs and a positive annualized Sharpe. With no champion, a model currently auto-wins.
- **Training env:**
  - random episode starts
  - allow resize or close while a trade is open
  - check TP/SL against high/low
  - per-symbol spread and slippage
- **Reward:** drop the windowed Sharpe bonus, which dominates the reward.
- **LSTM training:** labels are computed on MinMax-scaled prices and there is no validation split.
- **Autonomy loop:** it blocks on a subprocess inside async code. Canary P&L is not filtered by start time or magic number.
- **Drawdown peak:** persist the peak equity across restarts.
